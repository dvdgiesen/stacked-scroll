StackedScroll

A hardened library for stacked-page scrolling with pinned headers

Scroll down. Each section behaves like a page in a stack of papers: read through the content while the header stays pinned, then the next page slides up to take its place.

This demo uses StackedScroll, an idiomatic GSAP 3.13+ (ScrollTrigger + Observer) library extracted from rotyounges.com. It solves the edge cases that break every naive implementation:

  • Two-phase GSAP pinning & 3 transition modes — switch live between bottom-up, from-right (newspaper turn), and from-left (card swipe) with ScrollTrigger.observe() touch-swipe.
  • Deep links & collapsible content anchoring — scrollTo() avoids the offsetParent trap, and collapsing an accordion under a pin automatically anchors window.scrollY.
  • Short last panel & adjacent short buffers — an automatic end-spacer, pin-end clamping, and synthetic settle buffers keep every section handoff clean.
  • Fullscreen & rotation guard — prevents ScrollTrigger.refresh() and phone rotation from detaching pinned DOM nodes or reloading <iframe> embeds.

The stacked-pages mechanic

This section is taller than your viewport. Scroll through its body first. Only once you reach the bottom does the next section begin to slide over it.

That is the core difference between this effect and a simple sticky header. With sticky positioning alone, the header releases as soon as its container scrolls out. Here, the entire panel stays visually locked until you have consumed its content, producing a hard cut to the next section.

How the deep-link fix works

01 — Pin start logic

If a panel is shorter than the viewport, it pins immediately at start: "top top". If it is taller, it waits until its own bottom reaches the viewport bottom with start: "bottom bottom".

02 — pinSpacing: false

By disabling ScrollTrigger's default reserved scroll space, the next panel can slide up and cover the pinned one the moment the handoff begins.

03 — The offsetParent trap

When GSAP pins a panel, it sets position: fixed. That makes offsetTop and offsetParent unreliable for computing a target's document position — the classic deep-link bug. StackedScroll avoids them entirely.

04 — Natural height sum

offsetHeight is a panel's own natural size; fixed positioning changes its offset, never its size. Summing preceding panels gives the target panel's true document top.

05 — Same-tick rect diff

getBoundingClientRect() on the target and its panel share the same live viewport coordinate space. Their difference is the target's true offset within its panel.

06 — Header compensation

Each scrollTo() call subtracts the target section's own header height, so the pinned header never obscures the destination.

Interactive Feature 02 — Collapsible Content Scroll Anchoring

"Read more / Show less" inside a pinned section

When you reach the bottom of a tall section, GSAP pins it (position: fixed) and locks an inline height on its .pin-spacer, which disables native browser CSS Scroll Anchoring. Expand the archival notes below, scroll to the bottom of the expanded notes so this section pins, and click Show less — scroller.refresh() reads the pre-refresh height via ScrollTrigger's refreshInit hook and shifts window.scrollY upward so The Highlight does not overlap you.

Archival Note A — Why native overflow-anchor fails under pin

Browser scroll anchoring only triggers when layout shifts above the viewport inside normal document flow. Once a section reaches start: "bottom bottom", GSAP sets position: fixed and locks the .pin-spacer height.

Archival Note B — How ScrollTrigger. refreshInit solves it

Before ScrollTrigger.refresh() unpins the DOM to re-measure, StackedScroll records each section's live .pin-spacer height. When the refresh completes, it compares the new natural height against the old one and clamps window.scrollY by the exact collapsed delta.

Visual rhythm

Mixing tall and short panels gives editorial rhythm without breaking the physics of the scroll. Tall panels are read; short panels are seen.

Because the spacer is sized generically against the last panel, reordering sections does not require code changes. The demo deliberately places a short panel last to prove the spacer fix.

Interactive Feature 03 — Fullscreen & Orientation-Rotation Guard

Keep fullscreen video & <iframe> embeds alive across resizes

Normally, calling ScrollTrigger.refresh() (or rotating a phone, which triggers GSAP's internal matchMedia listener) temporarily unwraps and re-parents every pinned DOM node — immediately exiting browser fullscreen and reloading any child <iframe>. StackedScroll wraps each trigger's revert() and refresh() while fullscreen (or setFullscreenGuard(true)) is active.
