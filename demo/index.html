Finding 01 — Two-Phase Sticky + Pin Choreography (Tall vs. Short Panels)

Plain CSS position: sticky can keep a header visible while its section scrolls, but it cannot hold a finished section in place while the next section slides over it. StackedScroll pairs CSS sticky headers with height-aware GSAP ScrollTrigger start rules:

  • Tall sections (offsetHeight ≥ viewportHeight): start: "bottom bottom" — let the reader scroll naturally through all content first, then pin the final view.
  • Short sections (offsetHeight < viewportHeight): start: "top top" — no internal scrolling is needed, so the section pins as soon as its top reaches the top of the viewport.

Finding 02 — Why pinSpacing: false Is Essential (and Its Pointer-Events Gotcha)

By default, GSAP's pin: true inserts a .pin-spacer wrapper that reserves extra vertical scroll space equal to the pin duration. Setting pinSpacing: false disables that dead space so the next section immediately slides over the pinned one.

Crucial finding for horizontal page turns (from-right / from-left): While an incoming panel is translated off to the side, its parent .pin-spacer still rises vertically from the bottom across the full viewport width. StackedScroll automatically sets .pin-spacer { pointer-events: none } and .panel { pointer-events: auto } so the invisible wrapper never blocks links or buttons on the underlying pinned page.

Finding 03 — The offsetParent & getBoundingClientRect() Trap Under position: fixed

Once a user scrolls past Section 1, GSAP pins Section 1 with position: fixed; top: 0px. Under the CSSOM View specification, any element with position: fixed has offsetParent === null and reports its viewport-relative offset instead of its document offset. Calling element.offsetTop or getBoundingClientRect().top + window.scrollY on a pinned section returns window.scrollY — landing hundreds of pixels off target.

StackedScroll.scrollTo() computes every target's true document position by summing the natural offsetHeight of preceding sections (plus any synthetic settle buffers) and adding a same-tick getBoundingClientRect() delta between the target section and any inner offsetElement, minus sticky header height.

Finding 04 (Interactive Demo) — Collapsible Content Scroll Anchoring

Why native CSS overflow-anchor fails inside a pinned section

When you reach the bottom of a section to click "Show less" on an accordion, GSAP has already pinned that section (position: fixed) and locked an inline height on its .pin-spacer. Because the inline height is locked when the content collapses, native browser Scroll Anchoring never fires; and when ScrollTrigger.refresh() runs, GSAP restores the pre-collapse scroll position — stranding you inside the next section.

Finding 05 — Short Sections & Synthetic Settle Buffers

Immediate pin at start: "top top"

This section's content fits on a single screen, so it pins the instant its header reaches the top of the viewport — while Section 04 slides up (or across) to cover it.

When two short sections appear back-to-back, they don't provide enough natural scroll distance for the first pin to release before the second engages. StackedScroll automatically injects and reuses a synthetic .stacked-scroll-buffer element between consecutive short sections so their pin windows never overlap.

Finding 06 (Interactive Demo) — Fullscreen Video & Orientation-Rotation Guard

Keep fullscreen video & <iframe> embeds alive across resizes

Normally, calling ScrollTrigger.refresh() (or rotating a phone, which triggers GSAP's internal matchMedia("(orientation: portrait)") listener) temporarily unwraps and re-parents every pinned DOM node — immediately exiting browser fullscreen and reloading any child YouTube/Vimeo <iframe>. StackedScroll wraps each trigger's revert() and refresh() while fullscreen (or setFullscreenGuard(true)) is active.
